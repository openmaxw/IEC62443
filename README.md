# IEC 62443 协同工作台

让输入真正走到交付。

这是一个面向 IEC 62443 项目场景的前端工作台原型，用于帮助业主、集成商与设备商围绕同一项目上下文完成输入整理、设计响应、能力声明、差距闭环与交付汇总。

## 项目定位

本项目不是自动合规判定工具，也不是替代专家判断的黑盒生成器。

它的目标是把 IEC 62443 项目推进过程中常见的几段关键翻译显式化、结构化：

- 业务输入 → 风险关注
- 风险关注 → 设计响应
- 设计响应 → 能力声明
- 能力声明 → 差距闭环与交付

换句话说，它更像一个围绕单一项目对象运行的协同工作台，而不是一组彼此分散的页面。

## 当前能力

当前版本已经具备一条可连续推进的主链：

- 业主输入
- 集成设计
- 设备能力声明
- 匹配与闭环
- 追溯与交付汇总

系统当前支持：

- 项目级状态统一维护
- 多阶段结果连续流转
- 结果页、闭环页、追溯页和交付页联动
- 基于本地规则的风险翻译、设计建议与匹配分析
- 本地存储下的断点恢复与演示项目加载

## 主流程

```text
工作台
  -> 业主输入与风险翻译
  -> 集成设计与能力需求分配
  -> 设备能力声明
  -> 匹配分析与差距闭环
  -> 追溯查看与交付汇总
```

每一阶段都以“可交接结果”为目标，而不是只停留在表单输入。

## 页面结构

- `/`：首页
- `/dashboard`：工作台
- `/owner`：业主输入
- `/owner/result`：业主交接结果
- `/integrator`：集成设计
- `/integrator/result`：设计结果
- `/vendor`：设备能力声明
- `/vendor/result`：设备声明结果
- `/selection`：匹配与闭环
- `/translation-center`：追溯链
- `/report`：交付中心
- `/learning`：学习模式

## 技术结构

- `React 19`
- `Vite`
- `React Router`
- `Context + hooks`
- `CSS Modules`

项目当前已逐步形成以下分层：

- `schema`：核心对象正式结构
- `normalize`：状态入口归一化
- `selector / view model`：页面消费契约
- `pages`：任务输入、结果展示与交互流程

## 本地运行

安装依赖：

```bash
npm install
```

启动开发环境：

```bash
npm run dev
```

构建：

```bash
npm run build
```

运行最小契约测试：

```bash
npm run test:contract
```

## 当前边界

- 当前仍是前端原型，未接入后端、账户体系或真实设备数据库
- 风险翻译、规划建议和匹配分析依赖本地规则与模板，不替代正式风险评估
- 输出适合前期协同、方案整理与交付准备，不等同于认证结论
