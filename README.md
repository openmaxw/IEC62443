# IEC 62443 需求澄清与响应工作台

**将模糊安全诉求转化为标准化项目输入与清晰响应路径。**

本系统是一个面向 IEC 62443 项目前期沟通的需求澄清与响应工作台，用于帮助业主、集成商、设备商和项目团队围绕同一项目上下文，理解工业网络安全需求应如何被表达、转译、响应、匹配和交付。

它不是让用户一开始就掌握 IEC 62443 的所有概念，而是通过一条可操作的流程，引导用户从“我想提升工业安全，但还说不清楚”逐步走向“我知道应该提供哪些输入、对方应该如何响应、哪些差距需要处置”。

## 系统定位

本系统适合用于 IEC 62443 项目前期的需求澄清、方案沟通、能力匹配和交付准备。

它的核心价值不是自动给出合规结论，而是帮助项目相关方建立共同语言和响应逻辑：

```text
模糊安全诉求
  -> 标准化项目输入
  -> 风险关注与要求转译
  -> 设计响应
  -> 能力声明
  -> 匹配闭环
  -> 项目追溯与交付摘要
```

换句话说，本系统更像一个“项目认知引导与响应工作台”，帮助多方先把需求、设计、能力和差距关系说清楚，再进入后续更深入的评估、方案设计、产品选型和工程合作。

## 适合谁使用

### 业主方

适合已经意识到需要提升工业网络安全，但还难以清晰表达需求的企业用户。

系统可以帮助业主方：

- 梳理业务场景、关键系统、外部连接和维护方式
- 表达安全担忧、业务后果和验收关注
- 将模糊诉求整理为后续设计可使用的标准化项目输入
- 理解哪些信息会影响分区、边界、通信和能力需求

### 集成商

适合需要基于业主输入形成网络安全设计响应的系统集成商或工程团队。

系统可以帮助集成商：

- 将项目输入转化为设计依据
- 形成 Zone / Conduit、通信路径、边界控制和访问控制思路
- 生成项目级能力需求
- 说明设计为什么这样做，以及如何回应业主风险关注

### 设备商

适合需要面向项目需求说明产品能力、证据和限制条件的设备或产品供应商。

系统可以帮助设备商：

- 将产品能力映射到具体项目需求
- 声明能力满足情况、证据类型、适用边界和外部依赖
- 提前说明哪些能力需要系统集成、配置条件或补偿措施
- 减少项目后期才暴露能力边界的问题

### 项目负责人 / 顾问 / 评审者

适合需要组织多方沟通、复核需求与设计关系、整理阶段性交付材料的项目角色。

系统可以帮助他们：

- 查看项目状态和缺失输入
- 复核项目输入、风险关注、设计响应、能力声明和差距之间的对应关系
- 整理匹配闭环记录和交付摘要
- 为后续咨询、评审、方案深化和商务沟通建立共同语境

## 推荐使用方式

### 快速体验路径

适合第一次了解系统价值。

1. 进入 **项目总览**
2. 加载演示项目
3. 查看 **项目追溯链** 中的追溯矩阵
4. 查看 **匹配闭环** 中的差距处置状态
5. 查看 **交付摘要** 中的阶段成果

### 正式澄清路径

适合从一个真实或半真实项目需求开始梳理。

1. 在 **需求澄清** 中填写项目场景、安全担忧、关键对象和约束条件
2. 查看 **项目输入摘要**，确认业主输入是否足够清晰
3. 在 **设计响应** 中形成分区、通信、边界控制和能力需求
4. 在 **能力声明** 中录入产品能力、证据、依赖和限制
5. 在 **匹配闭环** 中确认满足项、差距项、补偿措施和责任方
6. 在 **项目追溯链** 中复核输入到响应的对应关系
7. 在 **交付摘要** 中汇总阶段性材料

### 复核评审路径

适合项目经理、顾问或评审人员快速查看整体一致性。

1. 查看 **项目总览**，了解当前进度和缺失输入
2. 查看 **项目追溯链**，确认输入、风险、设计、能力和差距是否连贯
3. 查看 **匹配闭环**，确认差距是否已处置
4. 查看 **交付摘要**，检查阶段成果是否具备继续推进的基础

## 页面功能说明

- **首页**：说明系统定位、适用场景和核心价值
- **项目总览**：查看项目进度、缺失输入、推荐动作和阶段状态
- **需求澄清**：帮助业主方表达业务场景、安全担忧、关键对象和验收关注
- **项目输入摘要**：将需求澄清结果整理为可交接的标准化项目输入
- **设计响应**：帮助集成商形成分区、通信、边界控制和能力需求
- **设计响应摘要**：展示设计依据、能力需求和需求—设计对应关系
- **能力声明**：帮助设备商声明产品能力、证据、适用边界、依赖和限制
- **能力声明摘要**：展示产品能力对项目需求的响应情况
- **匹配闭环**：识别满足、部分满足、不满足和外部补偿项，并记录处置措施
- **项目追溯链**：通过矩阵查看项目输入、风险关注、设计响应、能力需求和差距状态之间的关系
- **交付摘要**：汇总阶段成果、闭环状态和 IEC 62443 映射依据，并支持生成 Markdown 摘要
- **使用手册**：说明系统使用路径、页面功能、角色用法和术语速查

## 系统优势

### 1. 降低 IEC 62443 前期沟通门槛

用户不需要一开始就能完整描述 IEC 62443 要求。系统从业务场景、安全担忧和验收关注出发，引导用户逐步形成更结构化的项目输入。

### 2. 让需求、设计和能力响应处在同一上下文

业主输入、风险关注、设计响应、能力声明和差距处置不是分散的文档，而是在同一项目对象下连续流转，便于多方对齐。

### 3. 帮助集成商形成可解释的设计依据

设计响应不只是填写方案描述，而是能够回到项目输入、风险关注和能力需求，说明为什么需要这样的分区、通信路径和边界控制。

### 4. 帮助设备商更准确地回应项目需求

设备商不是简单罗列产品功能，而是围绕项目能力需求说明满足情况、证据、依赖和限制，便于提前识别能力边界。

### 5. 提前暴露差距并形成闭环记录

系统将能力匹配结果转化为待处置项，要求明确补偿措施、责任方、验收影响和残余风险，减少问题在项目后期才暴露。

### 6. 提供可追溯的项目沟通材料

项目追溯链和交付摘要可以帮助用户回看“输入从哪里来、设计响应了什么、能力是否满足、差距如何处置”，为后续评审和合作提供依据。

## 当前边界

本系统是前端原型和方法演示工具，当前不等同于正式工程系统。

请注意：

- 系统输出不构成正式风险评估结论
- 系统输出不构成认证、合规或审计结论
- 系统输出不替代详细工程设计、专家评审或现场验证
- 本地规则、映射和建议需要结合具体项目背景复核
- 演示数据为虚构示例，不代表任何真实企业、产品或认证背书
