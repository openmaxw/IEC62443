# 当前系统后续增强清单

## 1. 文档目的

本文档用于记录基于现有系统架构的后续增强方向。

前提共识：
- 当前系统主流程已经打通
- 当前系统已具备项目状态管理、规则引擎、结果页、闭环与交付中心
- 后续工作重点应是“深化与补强”，而不是推翻式重构

## 2. 当前系统基线

当前已完成的基础能力包括：
- 单一项目状态对象与本地持久化
- 工作台进度管理、缺失输入检查与下一步推荐
- 业主输入结果、集成设计结果、设备声明结果
- 选型匹配、差距闭环、追溯中心与交付中心
- 风险翻译引擎、规划建议引擎、匹配分析引擎

以下 backlog 以此为基线展开。

## 3. P0：继续增强现有主流程的可交付性

### P0-1 继续增强 Report Center
目标：把当前交付汇总页进一步强化为可直接用于汇报与交接的交付中心。

建议项：
- 细化交付项卡片与状态说明
- 增加按角色查看交付物的视图
- 增加更完整的导出对象定义
- 让闭环项与交付项的对应关系更清晰

涉及方向：
- `src/pages/Report/ReportCenter.jsx`
- `src/data/deliverables.js`
- `src/utils/reportGenerator.js`

### P0-2 继续增强 Translation Center
目标：让追溯中心承担更多“解释复用”能力。

建议项：
- 增加从业务驱动到 FR 重点的解释链展示
- 增加从控制目标到能力项的映射说明
- 增加从差距项回溯到原始输入的定位信息
- 统一 Owner / Integrator / Selection 中的说明口径

涉及方向：
- `src/pages/TranslationCenter/TranslationCenter.jsx`
- `src/utils/riskEngine.js`
- `src/utils/planningEngine.js`
- `src/utils/matchPresentation.js`

### P0-3 强化 Selection 的闭环编辑体验
目标：让差距闭环不只是结果浏览，而是更完整的责任分配与处理页。

建议项：
- 明确每个差距项的责任方
- 强化补偿措施、验收影响、残余风险输入
- 区分“待处理 / 已处理 / 已接受残余风险”状态
- 优化高严重度与外部依赖项的提醒

涉及方向：
- `src/pages/Selection/SelectionMatrix.jsx`
- `src/data/matchStatuses.js`
- `src/context/ProjectContext.jsx`

## 4. P1：深化各阶段输入与输出质量

### P1-1 深化 Owner 输入结构
目标：让业主输入更稳定地支撑后续设计与解释。

建议项：
- 增强关键资产和关键系统输入结构
- 细化维护接入、第三方接入与外联边界
- 增强连续性要求与合规补充说明
- 优化访谈项之间的逻辑提示

涉及方向：
- `src/pages/Owner/OwnerInterview.jsx`
- `src/hooks/useRiskAssessment.js`
- `src/utils/riskEngine.js`

### P1-2 深化 Integrator 的设计依据表达
目标：让集成设计不仅有结果，还有更完整的设计理由。

建议项：
- 强化 zone 划分理由
- 强化 conduit 设置依据
- 强化通信方向、用途和必要性说明
- 强化待设备商确认能力项的来源解释

涉及方向：
- `src/pages/Integrator/IntegratorWorkspace.jsx`
- `src/pages/Integrator/IntegratorResult.jsx`
- `src/utils/designInputEngine.js`
- `src/utils/planningEngine.js`

### P1-3 深化 Vendor 声明结构
目标：让设备声明更贴近项目核对语境。

建议项：
- 细化证据类型结构
- 细化依赖项和适用边界
- 细化限制条件与已知风险
- 增加项目要求来源展示

涉及方向：
- `src/pages/Vendor/VendorCapability.jsx`
- `src/pages/Vendor/VendorResult.jsx`
- `src/data/capabilities.js`

## 5. P2：补强原型可验证性与演示能力

### P2-1 增加更明确的演示与冒烟验证资料
目标：让现有原型更易于演示、验收和回归检查。

建议项：
- 补充关键页面演示路径说明
- 明确 demo project 覆盖哪些场景
- 细化 smoke test 步骤与期望结果

涉及方向：
- `docs/冒烟测试方案.md`
- `src/data/demoProject.js`
- `src/pages/Dashboard/Dashboard.jsx`

### P2-2 增强导出与打印体验
目标：让现有结果页更适合外部沟通。

建议项：
- 在 JSON 导出之外增加更适合交付阅读的结构
- 优化打印样式
- 统一结果页版式

涉及方向：
- `src/utils/reportGenerator.js`
- `src/pages/*Result*.jsx`
- `src/App.css`

## 6. 暂不建议的方向

基于当前系统阶段，以下事情暂不应优先：
- 引入复杂后端与权限体系后再回头梳理前端流程
- 在没有统一数据口径前接入真实设备库
- 过早追求自动合规结论或“自动认证”表述
- 推翻当前工作台 + 结果页 + 中心页的整体结构

## 7. 优先级结论

如果按当前价值排序，建议优先顺序为：
1. 强化 `Report Center` 与 `Translation Center`
2. 强化 `Selection` 的闭环编辑与责任归属
3. 深化 `Integrator` 和 `Vendor` 的解释与声明结构
4. 最后再增强导出、演示与更广泛验证资料
