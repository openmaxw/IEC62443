# IEC 62443 原型最小 Smoke Test 方案

## 1. 文档目的

本文档用于基于当前系统实现，定义一套低维护成本的最小冒烟测试路径，优先发现以下问题：
- 路由白屏或跳转异常
- 项目状态兼容失败
- 草稿恢复失效
- 结果页前置条件缺失导致的渲染错误
- 演示项目链路断裂
- Selection / Translation / Report 等中心页与主流程脱节

## 2. 当前测试原则

在当前前端原型阶段，Smoke Test 目标不是覆盖所有细节，而是确认：
- 主流程能走通
- 关键结果页能打开
- 旧缓存不会导致崩溃
- 演示项目可以支撑完整展示

建议执行顺序为：
1. 先做演示项目全链路检查
2. 再做空白项目最小推进
3. 再做刷新恢复与旧缓存兼容
4. 最后做少量重点回归

## 3. Smoke-1：演示项目全链路可访问

### 步骤
- 打开 `/dashboard`
- 点击“加载演示项目”
- 依次访问以下页面：
  - `/owner`
  - `/owner/result`
  - `/integrator`
  - `/integrator/result`
  - `/vendor`
  - `/vendor/result`
  - `/selection`
  - `/gap`
  - `/translation-center`
  - `/report`
  - `/learning`

### 期望结果
- 页面均可正常打开
- `/gap` 会自动跳转到 `/selection`
- 无白屏、无 React error overlay、无明显控制台红错
- Dashboard 中阶段状态、缺失输入、下一步建议能正常显示
- Report Center 中交付项和闭环统计能正常显示

### 重点关注
- 演示数据是否覆盖 Owner / Integrator / Vendor / Selection / Report 全链路
- Translation Center 是否能读取完整追溯信息
- 结果页是否存在深层字段读取导致的空值异常

## 4. Smoke-2：空白项目最小推进链路

### 步骤
- 清空 `localStorage` 和 `sessionStorage`
- 打开 `/dashboard`
- 确认系统进入空白项目状态
- 进入 `/owner`
- 填写最小必要信息并生成业主结果
- 进入 `/integrator`，填写最小设计草案并生成集成结果
- 进入 `/vendor`，录入最小能力声明并生成设备结果
- 进入 `/selection`，确认匹配结果可生成
- 进入 `/report`，确认交付中心可以读取当前结果

### 期望结果
- 整个流程可推进
- Dashboard 不会因为空状态而报错
- 每个阶段在前置不足时给出可理解空态或提示，而不是直接崩溃
- 生成结果后，Dashboard 阶段完成度与推荐下一步能够更新

### 重点关注
- `useProjectStatus()` 的阶段判断是否正确
- 结果页在最小输入下是否还能稳定展示
- Selection 和 Report 是否正确响应新增数据

## 5. Smoke-3：草稿刷新恢复

### 步骤
- 在 `/owner` 填写到一半但不提交最终结果，刷新页面
- 在 `/integrator` 填写到一半但不提交最终结果，刷新页面
- 在 `/vendor` 填写到一半但不提交最终结果，刷新页面

### 期望结果
- 草稿内容仍可恢复
- 页面刷新后不白屏
- 不出现循环更新、maximum update depth、render-phase update 等错误
- Dashboard 在草稿存在时仍能正常读取当前项目状态

### 重点关注
- 本地 state 与 Context 同步是否稳定
- `localStorage` / `sessionStorage` 是否都能保持一致恢复
- 草稿恢复后结果页与工作台是否还能正常读取项目数据

## 6. Smoke-4：旧缓存兼容

### 步骤
- 手动写入一个旧版本项目状态到 `localStorage` 或 `sessionStorage`
- 旧状态可故意缺少以下较新字段：
  - `gapClosure`
  - `deliverables`
  - `selectionAnalysis`
  - `vendorCatalog`
  - 其他嵌套默认字段
- 打开 `/dashboard`
- 继续访问 `/owner/result`、`/integrator/result`、`/vendor/result`、`/selection`、`/report`

### 期望结果
- 系统通过 `normalizeState()` 自动补齐默认结构
- 页面不崩溃
- 缺失数据表现为空态或默认值，而不是报错

### 重点关注
- `ProjectContext.jsx` 中的默认值与 normalize 是否覆盖所有新增字段
- hooks 是否对旧字段和新字段都兼容读取

## 7. Smoke-5：结果页前置条件保护

### 步骤
- 在没有业主结果的情况下直接打开 `/owner/result`
- 在没有集成结果的情况下直接打开 `/integrator/result`
- 在没有设备声明的情况下直接打开 `/vendor/result`
- 在没有匹配结果的情况下直接打开 `/selection`
- 在数据未齐全时打开 `/translation-center` 和 `/report`

### 期望结果
- 页面进入空态、提示态或最小展示态
- 不出现直接访问深层字段造成的崩溃
- 用户能看到下一步建议或缺失说明

## 8. Smoke-6：工作台与中心页联动

### 步骤
- 分别在只完成 Owner、完成 Owner + Integrator、完成全流程三种状态下打开 `/dashboard`
- 检查阶段卡片、缺失输入、下一步建议
- 打开 `/translation-center` 检查追溯链是否随数据变化更新
- 打开 `/report` 检查交付项状态与闭环统计是否同步变化

### 期望结果
- Dashboard 阶段状态与真实数据一致
- Translation Center 能根据已有阶段展示对应追溯内容
- Report Center 的交付项状态与闭环数量同步变化

## 9. 推荐执行方式

### 人工执行优先
当前建议优先人工执行以下四组：
- Smoke-1 演示项目全链路
- Smoke-2 空白项目最小推进
- Smoke-3 草稿刷新恢复
- Smoke-4 旧缓存兼容

### 自动化优先级
如果后续补自动化，建议优先把以下路径转为 Playwright：
- 演示项目全链路可访问
- 旧缓存兼容加载
- Dashboard 阶段状态与下一步推荐
- `/gap` 重定向到 `/selection`

## 10. 执行结论模板

每次 Smoke Test 可使用以下最简结论记录：
- 日期：

- 执行范围：Smoke-1 / 2 / 3 / 4 / 5 / 6
- 结果：通过 / 部分通过 / 未通过
- 主要问题：
- 是否阻塞演示或继续开发：是 / 否
