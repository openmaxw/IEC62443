# UI 统一规划与页面保留清单

## 1. 文档目的

本文档用于在系统重构前明确以下内容：
- 当前系统中哪些页面、功能和信息应被保留
- 每个页面未来应采用怎样统一的 UI 架构
- 每类页面的样式效果、信息层级和交互模式应如何规范
- 哪些视觉元素和填写方式应被统一约束

本文档不是视觉稿，也不是前端实现细节文档，而是用于你审核“哪些内容保留、哪些内容统一、未来页面应该长什么样”的评审基线。

---

## 2. 总体判断

当前系统已经具备以下应保留资产：
- 单一项目状态驱动的主流程
- Dashboard 工作台
- 业主 / 集成商 / 设备商 / 闭环 / 交付五大阶段
- 结果页与追溯页的基本逻辑
- 本地规则引擎驱动的风险、规划、匹配和报告能力
- 演示项目加载能力
- 本地持久化与阶段状态恢复能力

因此，重构目标不是删除这些能力，而是：
- 保留业务主线
- 保留关键功能
- 统一页面骨架
- 统一信息呈现方式
- 统一交互风格
- 统一视觉语言
- 减少页面之间的结构差异和临时写法

---

## 3. 必须保留的关键功能

以下功能视为重构期间不可丢失的“保留项”：

### 3.1 项目级能力
- 项目初始化 / 重置
- 加载演示项目
- 本地存储恢复项目上下文
- 工作台查看全局进度与下一步建议
- 跨页面保持同一项目上下文

### 3.2 阶段级能力
- 业主输入与风险翻译
- 集成设计输入与设计结果生成
- 设备能力声明与能力结果生成
- 选型匹配与差距闭环
- 交付汇总与导出
- 翻译中心追溯查看
- 学习模式辅助说明

### 3.3 结果级能力
- 每一阶段都应有“输入页”和“结果页 / 摘要页”概念
- 结果页必须可回看
- 结果页必须可作为下一阶段输入依据
- 结果页必须体现摘要、重点、未决项和下一步动作

## 4. 统一 UI 总原则

### 4.1 页面布局统一原则
未来除首页外，所有业务页面默认采用统一五区结构：

1. 页面标题区
2. 状态呈现区
3. 主内容区
4. 解释备注区
5. 底部动作区

其含义如下：

#### 页面标题区
用于呈现：
- 当前阶段编号
- 页面标题
- 所属项目名称
- 当前步骤名或当前视图名

#### 状态呈现区
这是后续所有页面都要统一增强的核心区域，必须固定存在。
用于呈现：
- 当前阶段完成状态
- 关键输入是否齐备
- 当前页面输出物是什么
- 与上下阶段的关系
- 需要提醒用户注意的状态标签

#### 主内容区
用于真正填写、查看、分析和编辑数据。
应尽量统一为以下几种内容块：
- 表格填写块
- 摘要卡片块
- 结果表格块
- 分组说明块
- 追溯链块

#### 解释备注区
用于解释：
- 本页为什么存在
- 当前字段怎么填
- 该页结果会影响谁
- 哪些内容属于假设 / 待确认 / 边界条件

此区域后续应统一为固定样式，不再让各页面自由发挥。

#### 底部动作区
用于统一放置：
- 上一步
- 保存
- 生成结果
- 下一步
- 进入下阶段

动作按钮的位置、颜色、优先级必须在所有业务页面保持一致。

## 5. 统一视觉规范

### 5.1 字体与文本语气规范
- 页面主标题：较粗，明确阶段身份
- 分区标题：中等粗细，层级统一
- 表头：中等偏粗，强调结构
- 普通正文：常规字重
- 提示信息：统一使用斜体
- 边界说明 / 限制说明 / 假设说明：统一使用斜体 + 次级颜色
- 风险提醒：不使用大段红字，采用标签 + 简短说明
- 空状态提示：使用斜体和低对比度说明文案

建议规范：
- 标题字体保持统一，不混用过多字号
- 页内最多 4 级文字层级
- 所有“提示、注释、说明、边界条件”统一斜体

### 5.2 配色规范
建议建立统一语义色，而不是页面自由设色：

- 主按钮色：深蓝或蓝绿色系，表示主要推进动作
- 次按钮色：浅灰蓝或白底描边，表示辅助动作
- 成功状态：柔和绿色
- 待完善状态：琥珀色 / 橙黄色
- 风险 / 缺口状态：低饱和红色
- 中性说明：灰蓝 / 中性灰

建议重点统一以下元素：
- 主按钮背景色
- 主按钮 hover 色
- 次按钮边框色
- 标签底色
- 表格边框色
- 表格表头底色
- 卡片边框色
- 页面分区背景色
- 提示说明文字颜色

### 5.3 表格规范
后续系统应优先使用表格作为填写和结果呈现主载体。

适用场景：
- 结构化输入
- 多字段并排比较
- 要求-能力匹配
- 差距项闭环
- 交付汇总
- 追溯链展示

表格统一要求：
- 表头固定使用浅底色
- 边框颜色统一，避免不同页面不同灰度
- 单元格内输入控件高度统一
- 单元格内提示文字统一斜体
- 行高统一
- 空值统一显示“未填写”或“待确认”
- 表格列标题命名风格统一
- 可编辑表格与结果表格视觉上应有轻微差异

## 7. 统一组件与页面元素规范

### 7.1 页面统一骨架组件
建议后续将所有业务页面统一建立在一个增强版页面壳之上，页面壳至少包含：
- 页面标题区
- 状态呈现区
- 主内容容器
- 解释备注区
- 底部动作区

当前 `src/components/ProjectFlow/ProjectStageShell.jsx:1` 可作为基础，但需要增强为真正的统一骨架。

### 7.2 状态呈现区统一规范
每个页面都要有一个固定的状态呈现区，建议统一包含：
- 当前阶段名
- 当前步骤名
- 当前输出物
- 完成度
- 是否存在缺失输入
- 影响下一阶段的关键提醒

状态呈现区建议采用：
- 左侧：项目与阶段状态摘要
- 右侧：标签、完成度、当前输出物

### 7.3 解释备注区统一规范
解释备注区建议统一使用固定样式：
- 标题：例如“填写说明”“边界说明”“审核提示”
- 正文：较短说明
- 提示语：统一斜体
- 禁止写成长篇大段说明
- 最多保留 3–5 条高价值提示

### 7.4 按钮规范
建议统一为四种按钮语义：
- 主按钮：推进流程，如“下一步”“生成结果”“进入下一阶段”
- 次按钮：辅助动作，如“保存”“查看摘要”
- 幽灵按钮：返回、取消、非强调动作
- 风险按钮：删除、重置等高风险操作

建议统一要求：
- 只有一个主按钮最突出
- “保存”通常不应比“下一步”更抢眼
- “重置项目”应使用风险样式，不与普通次按钮混淆

### 7.5 卡片规范
卡片只用于以下场景：
- 摘要信息
- 空状态提示
- 概览入口
- 首页展示

结构化数据编辑不建议主要依赖卡片，应以表格为主。

### 7.6 标签规范
统一标签语义建议：
- 已完成
- 待完善
- 风险项
- 待确认
- 外部补偿
- 不适用

同一标签颜色在全系统保持一致。

- 是否保留“每阶段输入页 + 结果页”的双页结构
- 是否保留“翻译中心”和“学习模式”作为横向页面
- 是否统一要求所有主业务页面都有“状态呈现区”和“解释备注区”
- 是否统一要求数据填写优先使用表格
- 是否统一要求提示说明文本使用斜体
- 是否统一按钮颜色、表格边框颜色、标签颜色
- 是否接受后续以统一页面壳替代页面各自独立布局

## 10. 统一设计令牌规范

本节用于定义后续整改时必须统一的基础视觉参数。这里不是最终 CSS 代码，而是用于约束实现方向的统一规则。

### 10.1 颜色系统

后续建议建立一套语义色，而不是页面自己定义颜色。

#### 主色
用于主流程推进、主按钮、阶段强调信息。

建议：
- `Primary-700`：深蓝绿色或深科技蓝，用于主按钮背景、关键强调标题
- `Primary-600`：主按钮默认色
- `Primary-500`：hover 或激活辅助色
- `Primary-100`：浅背景高亮区

设计意图：
- 要体现工业、安全、规划类系统的专业感
- 避免过于鲜艳的互联网蓝
- 避免偏娱乐化的高饱和颜色

#### 中性色
用于页面背景、边框、正文、辅助说明。

建议：
- `Neutral-900`：主标题和高优先文字
- `Neutral-700`：正文与次标题
- `Neutral-500`：辅助说明
- `Neutral-300`：边框
- `Neutral-200`：表格分隔线
- `Neutral-100`：卡片背景或浅分区背景
- `Neutral-050`：页面底色

#### 状态色
用于状态标签、风险、闭环、提示信息。

建议：
- `Success`：已完成 / 满足
- `Warning`：待完善 / 部分满足 / 待确认
- `Danger`：不满足 / 风险 / 高优先差距
- `Info`：说明 / 补充信息 / 次级提示
- `External`：外部补偿 / 外部依赖，可使用带灰蓝感的中间色

#### 禁止项
- 不允许每个页面自定义一套按钮色
- 不允许相同语义状态使用不同颜色
- 不允许同一页面出现过多高饱和强调色
- 不允许用纯红大面积铺底表达风险

### 10.2 字体层级

建议限制为 4 级主层级 + 2 级辅助层级。

#### 层级建议
- `H1`：页面主标题
- `H2`：分区标题
- `H3`：区块标题 / 表格标题
- `Body`：正文
- `Meta`：辅助说明、字段注释、提示文本
- `Label`：表头、标签、小标题

#### 字重建议
- `H1`：600–700
- `H2`：600
- `H3`：600
- `Body`：400–500
- `Meta`：400，必要时斜体
- `Label`：500–600

#### 斜体使用规则
以下内容统一斜体：
- 提示信息
- 填写说明
- 边界条件
- 假设说明
- 空状态提示
- 数据未齐备时的引导语

以下内容不应使用斜体：
- 主标题
- 主按钮
- 表格主数据
- 核心结果摘要数值

### 10.3 间距系统

建议所有页面采用统一间距节奏，避免页面密度忽大忽小。

建议基础单位：8px

推荐节奏：
- 超小间距：4
- 小间距：8
- 中间距：12 / 16
- 大间距：24
- 超大间距：32 / 40

使用原则：
- 表格内部 padding 保持一致
- 卡片之间间距固定
- 状态区与主内容区间距固定
- 标题区与状态区间距固定
- 底部动作区与正文区保持明显分割

### 10.4 圆角与边框

建议圆角风格统一，体现专业、规整，而不是过于圆润。

建议：
- 普通卡片：中小圆角
- 输入框：小圆角
- 表格：以直边为主，可在整体容器层面保留小圆角
- 按钮：统一中等圆角

边框建议：
- 输入框边框统一为中性灰
- 表格边框统一为浅中性色
- 卡片边框统一，不同模块不要使用不同灰度
- 状态块如果需要强调，优先用浅底色而不是粗重边框

### 10.5 阴影与层次

建议控制阴影使用频率。

规范建议：
- 普通信息卡片：轻微阴影或仅边框
- 表格：优先边框，不强调阴影
- 页面主容器：不需要明显浮起感
- 重点提示块：可使用轻阴影 + 浅底色

目标是保持“工程系统感”，而不是营销站式漂浮感。

## 11. 统一页面线框规范

本节将前述五区结构进一步明确为线框级约束，用于后续页面整改时统一实现。

### 11.1 标准业务页线框

所有主业务页默认采用以下结构：

1. 页面标题区
2. 状态呈现区
3. 主编辑 / 主结果区
4. 解释备注区
5. 底部动作区

建议阅读顺序必须固定：
- 先看页面身份
- 再看当前状态
- 再看核心内容
- 再看填写说明
- 最后执行动作

### 11.2 页面标题区线框

标题区应固定包含：
- 阶段编号
- 页面标题
- 项目名称
- 当前步骤 / 当前视图名
- 页面输出物名称

标题区表现要求：
- 左侧为标题信息
- 右侧为少量工具动作
- 不允许堆太多操作按钮
- 标题区信息需简洁，不应承担说明性长文本

### 11.3 状态呈现区线框

状态区是后续整改的重点，建议固定拆成两列：

#### 左列：项目状态摘要
- 当前阶段目的
- 当前页面输出物
- 是否完成关键输入
- 与上游 / 下游页面的关系

#### 右列：状态标签和进度摘要
- 当前步骤状态
- 缺失输入数量
- 关键提醒标签
- 完成度摘要

表现形式建议：
- 可采用摘要表 + 标签块
- 不建议做成随意排布的小气泡
- 信息必须一眼可扫读

### 11.4 主内容区线框

主内容区根据页面类型使用不同模式，但都要收敛到有限几种模板。

#### 模板 A：表格填写页
适用于：Owner / Integrator / Vendor 主输入页

结构：
- 分步骤页签
- 当前步骤说明
- 表格主体
- 行内提示
- 行级校验状态

#### 模板 B：摘要结果页
适用于：OwnerResult / IntegratorResult / VendorResult

结构：
- 结果概览摘要块
- 关键指标表
- 重点关注表
- 待确认 / 限制说明表
- 下一步动作提示

#### 模板 C：矩阵 / 闭环页
适用于：Selection / Gap

结构：
- 视图页签
- 匹配结果表
- 差距项表
- 补偿措施表
- 验收与残余风险表
- 闭环确认表

#### 模板 D：追溯 / 交付页
适用于：TranslationCenter / ReportCenter

结构：
- 汇总摘要表
- 映射 / 追溯关系表
- 阶段交付物块
- 导出或跳转动作

### 11.5 解释备注区线框

解释备注区必须固定位置，不得每个页面自由漂移。

建议包括：
- 本页目的
- 该怎么填写 / 阅读
- 对下游的影响
- 需要确认的边界
- 示例或注意事项

表现要求：
- 使用固定标题样式
- 说明不超过 5 条
- 所有提示信息统一斜体
- 备注区背景可使用浅中性色

### 11.6 底部动作区线框

底部动作区建议统一为：
- 左侧：返回 / 上一步
- 中间：保存
- 右侧：下一步 / 生成结果 / 进入下一阶段

动作优先级：
- 最右侧永远是主按钮
- 保存通常为次按钮
- 删除 / 重置不放在主流程操作组内

## 12. 页面类型细化规范

### 12.1 输入页统一规范

适用页面：
- `OwnerInterview`
- `IntegratorWorkspace`
- `VendorCapability`

统一要求：
- 默认有步骤页签
- 每个步骤主要使用表格录入
- 不建议使用长串自由表单
- 每一步有完成提示
- 页面顶部显示当前步骤在整页流程中的位置
- 页面底部按钮顺序一致

### 12.2 结果页统一规范

适用页面：
- `OwnerResult`
- `IntegratorResult`
- `VendorResult`

统一要求：
- 顶部先给摘要
- 中间给结构化结果表
- 下部给边界与说明
- 结果页必须能直接导向下一阶段
- 结果页应强调“交接意义”

### 12.3 矩阵页统一规范

适用页面：
- `SelectionMatrix`
- `GapCenter`

统一要求：
- 所有主信息必须以表格或矩阵表达
- 每行应能对应一个能力项或差距项
- 每一列应承担固定语义
- 不允许同一个字段在不同视图里换位置过多
- 每个状态值都要有统一标签样式

### 12.4 汇总页统一规范

适用页面：
- `Dashboard`
- `TranslationCenter`
- `ReportCenter`

统一要求：
- 优先概览 + 清单 + 跳转入口
- 摘要块和明细块分开
- 不堆砌大段文字
- 必须能支持“快速扫读”

## 13. 表格填写规范

### 13.1 表格字段布局

推荐统一三列或四列模式：
- 字段名
- 输入值 / 当前值
- 提示说明
- 状态 / 备注（可选）

对于复杂列表型数据，推荐列模式：
- 编号
- 名称
- 分类 / 类型
- 属性值
- 说明 / 限制
- 状态

### 13.2 输入控件规范

建议统一：
- 单行文本：统一高度
- 下拉选择：统一样式
- 文本域：统一最小高度
- 表格内按钮：统一小尺寸按钮规范
- 布尔选项：避免页面间混用 checkbox / button / select

### 13.3 表格空值规范

统一显示策略：
- 未填写：`未填写`
- 无数据：`暂无数据`
- 待确认：`待确认`
- 不适用：`不适用`

禁止：
- 有的页面留空白
- 有的页面显示 `-`
- 有的页面显示 `N/A`
- 有的页面显示不同中文说法

### 13.4 表格边框和表头规范

统一要求：
- 表头背景色统一
- 表头文字颜色统一
- 单元格边框颜色统一
- 行 hover 效果统一
- 可编辑表格和只读表格差异仅做轻度区分

## 14. 状态、标签与提示语规范

### 14.1 状态标签命名统一

建议系统统一使用以下状态词：
- 已完成
- 待完善
- 待确认
- 满足
- 部分满足
- 不满足
- 外部补偿
- 不适用
- 有风险
- 已闭环

后续代码和 UI 文案都应围绕这一套术语收敛。

### 14.2 提示语语气统一

建议提示语遵循以下风格：
- 简短
- 客观
- 可执行
- 避免营销式表达
- 避免口语化过强

例如：
- *请优先确认跨区通信是否存在远程维护路径。*
- *若该能力依赖上层系统实现，应在限制说明中明确。*
- *当前结果可作为下一阶段的输入依据，但不代表最终合规结论。*

### 14.3 风险提示规范

风险提示统一采用：
- 标签
- 一句话摘要
- 必要时补一行斜体说明

不建议：
- 大段整块红色文案
- 用颜色替代具体说明

## 15. 按钮与交互细节规范

### 15.1 按钮优先级

统一优先级：
- 一级：下一步 / 生成 / 进入下一阶段
- 二级：保存 / 查看 / 加载演示项目
- 三级：返回 / 取消
- 风险级：重置 / 删除

### 15.2 交互统一要求

- 相同动作在不同页面文案尽量一致
- “生成结果”不要有页面叫“完成”，有页面叫“提交”，有页面叫“输出”
- “保存草稿”与“下一步”要清晰区分
- 高风险动作必须二次确认
- 演示项目加载属于辅助动作，但必须保留明显入口

### 15.3 步骤导航规范

多步骤页面统一要求：
- 顶部有步骤标签或步骤条
- 当前步骤高亮
- 已完成步骤可回看
- 未完成后续步骤可进入，但需要有明确提示或约束策略

- 当前系统的业务页面和主流程应整体保留

## 19. 高级 UI 优化建议

本节不是基础统一规范，而是站在更高层次的视觉美学、信息架构和使用体验角度，对系统下一阶段 UI 优化提出的建议。

这里的核心判断是：
本系统不是展示型产品，而是一个高信息密度、强流程、强协同、强责任边界的工程工作台。
因此，UI 优化的目标不应是“更花哨”，而应是：
- 更清楚
- 更稳定
- 更可扫读
- 更有任务导向
- 更有阶段感和输出物感

## 20. 从使用者视角重新定义页面重点

### 20.1 用户第一眼最关心的不是视觉装饰，而是任务方向

对使用者来说，每个页面最重要的不是视觉特效，而是立刻理解以下问题：
- 我现在在哪个阶段
- 这个页面是填写页还是结果页
- 这个页面要我做什么
- 这个页面输出给谁
- 做完之后去哪里

因此，未来所有页面都应强化以下五种感受：
- 阶段身份感
- 页面任务感
- 当前状态感
- 输出物感
- 下一步动作感

这五项应优先于装饰性视觉设计。

## 21. 页面元素优先级模型

未来建议把每个业务页面元素统一划分为四层优先级：

### 第一层：页面任务
用于回答“本页的唯一核心目的是什么”。

应由以下元素承担：
- 页面标题
- 当前步骤名
- 输出物名称
- 状态摘要

### 第二层：关键信息
用于回答“当前最值得关注的内容是什么”。

应由以下元素承担：
- 完成度
- 当前结果数量
- 差距数量
- 风险数量
- 是否可进入下一阶段

### 第三层：主要工作区
用于真正完成任务。

包括：
- 输入表格
- 结果表格
- 对比矩阵
- 闭环表格
- 摘要统计块

### 第四层：解释信息
用于辅助理解，而不是抢主视线。

包括：
- 说明文字
- 假设条件
- 边界提醒
- 填写示例
- 风险补充说明

未来视觉实现时，必须确保第一层和第二层总是先于第三层和第四层被感知。

---

## 22. 页面类型的视觉策略应明确区分

### 22.1 输入页：应像工作表

适用页面：
- `OwnerInterview`
- `IntegratorWorkspace`
- `VendorCapability`

视觉目标：
- 稳定
- 规整
- 易填写
- 易校对
- 不干扰思路

视觉策略：
- 表格优先
- 背景克制
- 高亮少而准
- 说明区弱化但清晰
- 行列关系强于卡片装饰

### 22.2 结果页：应像汇报页

适用页面：
- `OwnerResult`
- `IntegratorResult`
- `VendorResult`

视觉目标：
- 一眼看懂结论
- 一眼看懂重点
- 一眼看懂要交给谁
- 一眼看懂下一步

视觉策略：
- 顶部先给摘要
- 中间给结果表
- 下方给边界与说明
- 结果页中的主按钮比输入页更明确

### 22.3 闭环页：应像责任与行动面板

适用页面：
- `SelectionMatrix`

视觉目标：
- 快速识别待处理项
- 快速识别责任归属
- 快速填写补偿措施
- 快速判断是否影响验收与残余风险

视觉策略：
- 闭环页不只是结果矩阵，而是处置工作台
- 差距项必须比满足项更突出
- 补偿措施和责任方必须是主视线内容

### 22.4 汇总页：应像控制塔和交付总览

适用页面：
- `Dashboard`
- `ReportCenter`
- `TranslationCenter`

视觉目标：
- 快速扫读
- 快速定位卡点
- 快速跳转到问题源头
- 快速理解全局状态

视觉策略：
- 强摘要
- 强入口
- 强阶段关系
- 弱装饰

---

## 23. 色彩策略的高级原则

### 23.1 色彩不是装饰，而是语义

本系统更适合低饱和、专业、稳定的工业信息系统风格，而不是高对比营销式风格。

建议长期坚持以下色彩逻辑：
- 主基调：冷静蓝灰 / 深青蓝
- 成功：低饱和绿
- 待补齐：琥珀 / 黄棕
- 风险：暗红 / 棕红
- 外部补偿 / 待确认：灰蓝中性色

### 23.2 高彩度区域应被严格控制

页面上真正应该明显着色的元素只有：
- 主按钮
- 当前步骤
- 状态标签
- 风险提醒
- 关键缺口

其他内容应优先依靠：
- 字重
- 层级
- 边框
- 背景分区
- 留白

来体现主次，而不是依赖大面积彩色背景。

---

## 24. Dashboard 的高级优化方向

### 24.1 Dashboard 应进一步强化“控制塔”感

Dashboard 是用户对系统建立整体认知的入口，应带来以下感受：
- 我知道当前整体到哪了
- 我知道哪一步卡住了
- 我知道下一步最值得做什么

因此未来建议进一步强化：
- 总体阶段进度
- 当前唯一推荐动作
- 演示项目与正式项目状态的区分
- 缺失输入的严重度排序

### 24.2 演示项目应有更明确的视觉提示

由于系统保留了演示项目加载能力，建议未来在加载演示项目时加入明确提示，例如：
- 顶部提示条
- Demo 标记
- 状态标签

防止用户误把演示数据当成正式项目数据。

---

## 25. SelectionMatrix 的高级优化方向

### 25.1 它不是普通表格页，而是核心处置页

从协同价值来看，闭环页是系统最关键的页面之一。
它不只是展示矩阵，而是：
- 差距识别
- 责任归属
- 补偿措施
- 验收影响
- 残余风险

因此未来应进一步把它优化成“责任与行动面板”，而不是普通结果页。

### 25.2 差距项的视觉优先级应高于普通满足项

未来建议：
- 满足项弱化到总览层
- 差距项强化到行动层
- 责任、措施、影响这三列成为主要视觉中心

---

## 26. 说明文字策略

### 26.1 说明文字应更少，但更锋利

当前系统已经统一了斜体说明规则，后续还应坚持：
- 每页说明控制在 2–4 条
- 每条只讲一件事
- 只说会影响当前操作的内容
- 不重复正文已经表达过的信息

优秀说明区的作用不是“讲很多”，而是“在用户最容易犯错的地方拉一把”。

---

## 27. 卡片与表格的高级分工

### 27.1 卡片只用于摘要和入口

卡片更适合：
- 首页展示
- 工作台推荐区
- 空状态
- 概览摘要
- 追溯摘要

### 27.2 表格才是系统主语言

表格更适合：
- 结构化录入
- 要求与能力比对
- 差距闭环
- 交付明细
- 追溯链映射

结论是：
本系统应明确坚持“卡片用于摘要，表格用于工作”。

---

## 28. 真正的统一不是颜色统一，而是节奏统一

高级统一感来自以下内容一致：
- 标题节奏一致
- 状态区位置一致
- 输入区阅读方式一致
- 说明区语气一致
- 动作区顺序一致
- 结果页摘要方式一致
- 闭环页责任列位置一致

未来若出现局部页面“看起来不统一”，优先检查这些节奏问题，而不是先检查颜色。

---

## 29. 下一阶段最值得投入的高级优化方向

### 29.1 建立页面类型视觉系统
把页面明确区分为：
- 输入页
- 结果页
- 闭环页
- 汇总页
- 学习 / 说明页

每类页面都应有稳定的视觉节奏。

### 29.2 建立信息优先级模型
每页都应明确：
- 第一眼看什么
- 第二眼看什么
- 第三眼才看什么

### 29.3 建立风险与责任语义系统
统一表达：
- 待确认
- 待补齐
- 高风险
- 外部补偿
- 已闭环

### 29.4 深化输入体验优化
建议重点继续优化：
- 表格行高
- 输入框密度
- placeholder 语气
- 编辑态 / 只读态区别
- 多列布局的扫读效率

### 29.5 战略性强化 Dashboard 与 SelectionMatrix
这两个页面最影响用户对系统“专业度”和“好用程度”的整体评价，优先级应高于辅助页视觉优化。

---

## 30. 最终结论

从更高层次的视觉美学和使用体验角度看，本系统下一步不应追求“更花哨”，而应追求：
- 更清楚
- 更稳定
- 更有任务导向
- 更可扫读
- 更像真正的工程决策协同工作台

后续所有 UI 优化，都应优先服务于：
- 减少迷路
- 减少误读
- 减少认知负担
- 增强阶段感
- 增强输出物感
- 增强责任与风险表达
