# 页面状态信息规则

## 1. 目标

页面顶部状态区只承载“决策型状态”，不承载用户在本页一眼即可看见的重复信息。

## 2. 必须显示的状态

仅保留以下三类：

- 当前最大阻塞是什么
- 当前是否可以进入下一步/交付
- 当前最重要的风险或缺口是什么

## 3. 不应显示的状态

以下信息默认不应占据顶部状态区：

- 本页标题已明确表达的内容
- 正文列表里一眼可见的重复数量
- 单纯说明“这是哪个页面”的信息
- 需要用户自己再解释一层才有价值的统计数字

## 4. 页面类型建议

### 4.1 编辑页
- 显示：是否可继续、缺什么、当前步骤是否已具备进入下一步条件
- 不显示：纯完成度数字堆叠

### 4.2 结果页
- 显示：是否已可交接、还缺什么、建议下一步
- 不显示：与正文摘要重复的统计信息

### 4.3 闭环页
- 显示：待闭环项、高风险项、当前交付阻塞
- 不显示：单纯“当前在闭环页”类说明

### 4.4 汇总页
- 显示：是否可交付、阻塞原因、优先处理项
- 不显示：低价值全局计数

## 5. 控制台边界

页面负责：
- 决策型状态
- 当前流程上下文
- 下一步建议

控制台负责：
- 原始对象状态
- 全量字段
- 中间计算结果
- 历史兼容映射

## 6. 实施原则

- 每个状态区最多 1 个 headline
- note 必须回答“为什么重要”或“下一步为什么是这个”
- pills 不超过 2–3 个，且必须能辅助判断
- 如果没有足够高价值信息，宁可弱化该状态区，而不是填充低价值数字
