# 基于现有实现的视觉与交互优化方案

## 1. 文档目的

本文档用于基于当前已完成的页面结构和工作流，整理后续视觉与交互优化方向。

重点不是推翻现有界面，而是在现有系统已经具备：
- 工作台主入口
- 分阶段页面
- 结果页交接节点
- 追溯中心与交付中心

的前提下，进一步提升：
- 可扫读性
- 状态辨识度
- 决策效率
- 页面之间的一致性

## 2. 当前视觉优化的前提认知

当前系统已经不是“单页表单集合”，而是具有明显流程主线的协同工作台，因此视觉优化应服从以下认知：
- 工作台优先展示状态、缺口、下一步
- 表单页优先展示任务与填写区
- 结果页优先展示结论、风险点、待确认项
- 中心页优先展示追溯关系、闭环状态和交付准备情况

换句话说，视觉层不应再把所有页面都做成同一种“长文档式说明页”。

## 3. 当前问题聚焦

结合现有页面职责，视觉与交互层后续主要应解决以下问题：
- 页面信息密度偏高时，关键状态不够突出
- 结果、说明、背景文字有时层级过近
- 不同结果页之间的摘要区、状态区、空态区仍可进一步统一
- 工作台与中心页已经承担全局导航职责，但视觉优先级还可继续强化

## 4. 全局视觉原则

### 4.1 先看状态，再看解释
所有页面都应优先让用户看到：
- 当前处于什么阶段
- 当前结果是否已具备
- 当前是否存在关键差距或待补齐项
- 下一步应该去哪里

解释性文本应服务于状态，而不是盖过状态。

### 4.2 颜色必须承担语义
颜色应继续用于表达：
- 当前阶段
- 已完成 / 已具备
- 待补齐 / 注意事项
- 风险 / 阻塞项
- 辅助说明与背景信息

避免为了装饰增加无明确含义的颜色层次。

### 4.3 结构必须服务于工作流
不同页面的结构重心应明确区分：
- Dashboard：进度、缺口、建议
- 输入页：任务说明、填写区域、即时反馈
- 结果页：结论、摘要、待确认项、解释细节
- 中心页：追溯、闭环、交付状态

### 4.4 减少大段说明压迫感
说明文字应尽量：
- 短段化
- 模块化
- 配合标题、标签、状态块展示
- 避免形成连续大段文案墙

## 5. 页面类型优化建议

### 5.1 Dashboard
优化目标：进一步强化它作为“项目控制台”的视觉中心地位。

建议方向：
- 强化 Hero 区的项目摘要、总进度和主 CTA
- 强化“下一步建议”卡片的优先级
- 让“缺失输入”与“阶段卡片”形成更清晰的主次关系
- 让阶段状态标签更利于快速扫读

### 5.2 Owner / Integrator / Vendor 输入页
优化目标：让填写页更像任务工作台，而不是说明页。

建议方向：
- 顶部摘要区统一呈现页面目的、角色、输出对象
- 表单区块之间形成清晰分组
- 关键字段与建议字段区分层级
- 对草稿、已填写、待补充状态给出更直接提示

### 5.3 Owner Result / Integrator Result / Vendor Result
优化目标：统一结果页的“摘要 -> 结论 -> 待确认 -> 解释”阅读顺序。

建议方向：
- 统一结果页顶部摘要区结构
- 统一状态标签、指标卡、空态卡表现
- 把关键结论放在前面，把解释细节放在后面
- 对待确认项、风险保留项、限制条件增强提醒样式

### 5.4 Selection
优化目标：把匹配与闭环页做成真正的决策页。

建议方向：
- 强化综合得分、状态分布和推荐等级的首屏可见性
- 对缺口项、高严重度项、外部依赖项做更明显分层
- 让补偿措施、验收影响、残余风险编辑区更清晰
- 避免结果浏览区和闭环编辑区互相抢视觉焦点

### 5.5 Translation Center
优化目标：让追溯中心更像“解释工作台”。

建议方向：
- 突出从业务输入到能力要求的主链路
- 降低非关键说明对主链的干扰
- 让不同列或不同区块之间的关联更直观
- 在缺失中间数据时提供清晰空态说明

### 5.6 Report Center
优化目标：让交付中心更像“交付状态总览”。

建议方向：
- 强化交付项是否具备的状态辨识
- 强化闭环项、高严重度、外部依赖的关键统计
- 提高“还缺什么才能交付”的可见性
- 对已具备入口与待补齐入口做更明确区分

## 6. 统一组件层建议

基于当前系统，以下视觉模式建议持续统一：
- Hero 摘要区
- 状态标签
- 指标卡
- 空态提示块
- 风险/警示提示块
- 结果摘要卡
- 模块标题与副说明层级

这可以减少不同页面各自演化造成的风格漂移。

## 7. 文案层级建议

### 7.1 标题层级
- 页面标题：表达当前核心任务
- 模块标题：表达当前内容区主题
- 指标标题：表达状态与结果摘要
- 辅助说明：解释背景、限制或阅读方式

### 7.2 文案书写方式
应优先使用：
- 任务语言
- 交接语言
- 风险与结果语言

减少：
- 纯背景介绍式长文案
- 重复说明系统用途的段落
- 和当前页面任务弱相关的泛化解释

## 8. 实施优先级建议

### 第一优先级
- Dashboard
- Selection
- Report Center

原因：这三页最直接影响用户对系统整体状态、差距闭环和交付完成度的判断。

### 第二优先级
- Owner Result
- Integrator Result
- Vendor Result
- Translation Center

原因：这些页面直接影响交接效率与解释质量。

### 第三优先级
- 各输入页的细节层级和字段提示优化
- 学习页与辅助说明页的风格统一

## 9. 结论

当前系统已经具备清晰的工作流和页面职责，视觉优化的重点不再是“重做界面”，而是：
- 强化状态与下一步
- 统一结果页结构
- 提高闭环与交付场景的可扫读性
- 让解释信息更好地服务于决策

后续所有视觉整改都应建立在这一现状之上推进。
