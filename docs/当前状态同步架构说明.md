# 当前状态同步架构说明

## 1. 目的

本文档用于说明当前系统中本地编辑态、Context 草稿态、结果态和持久化之间的关系，帮助后续开发在统一规则下修改状态逻辑，避免再次引入死循环、抖动更新和状态不同步问题。

---

## 2. 当前状态层次

### 2.1 本地编辑态
由页面内部 `useState` 持有。

典型页面：
- `OwnerInterview`
- `IntegratorWorkspace`
- `VendorCapability`
- `SelectionMatrix`

作用：
- 承载当前页面正在编辑但尚未明确提交的内容
- 支撑输入控件即时更新

特点：
- 渲染频率高
- 易产生对象新引用
- 不适合直接无保护地同步到全局状态

### 2.2 Context 草稿态
保存在 `ProjectContext` 中。

主要字段：
- `ownerProfile.draft`
- `integratorDesign.draft`
- `vendorCatalog.draft`
- `gapClosure.items`

作用：
- 页面切换时保留阶段内编辑结果
- 作为本地编辑态的持久化镜像

特点：
- 适合阶段内保存
- 不应与页面本地状态无条件双向同步

### 2.3 结果态
保存在 Context 中，作为阶段产物。

主要字段：
- `ownerProfile.assessment`
- `riskTranslation.profile`
- `integratorDesign.plan`
- `vendorCatalog.capabilities`
- `selectionAnalysis.results`
- `gapClosure.items`（保存后的闭环结果）

作用：
- 驱动结果页
- 为后续阶段提供输入
- 支撑交付中心和追溯中心

特点：
- 语义上应比草稿态更稳定
- 应由明确动作触发生成或保存

### 2.4 持久化态
保存在：
- `sessionStorage`
- `localStorage`

作用：
- 页面刷新恢复
- 演示项目加载后保留上下文

特点：
- 不应参与业务判断
- 只作为 Context 的落盘镜像

---

## 3. 推荐同步方向

### 3.1 输入页推荐方向
推荐采用：
- 本地编辑态 -> Context 草稿态

即：
- 页面本地状态是当前编辑主源
- Context 草稿态是镜像与持久化入口

限制：
- 回写必须先比较再更新
- Context 草稿反向回灌本地状态时也必须先比较

### 3.2 结果生成页推荐方向
推荐采用：
- 草稿态 / 本地态 -> 结果态

即：
- 通过“生成结果”“进入下一阶段”“保存闭环”等明确动作写入结果态
- 不应在普通输入变动时自动反复重建结果态

### 3.3 持久化推荐方向
推荐采用：
- Context -> Storage

即：
- 持久化层只负责保存当前 Context
- 不应主动影响页面本地编辑逻辑

## 4. 当前主要边界

### 4.1 业主阶段
- 本地编辑态：`OwnerInterview.formData`
- 草稿态：`ownerProfile.draft`
- 结果态：`ownerProfile.assessment` / `riskTranslation.profile`

### 4.2 集成阶段
- 本地编辑态：`IntegratorWorkspace.plan`
- 草稿态：`integratorDesign.draft`
- 结果态：`integratorDesign.plan`

### 4.3 设备阶段
- 本地编辑态：`VendorCapability.formData`
- 草稿态：`vendorCatalog.draft`
- 结果态：`vendorCatalog.capabilities`

### 4.4 闭环阶段
- 本地编辑态：`SelectionMatrix.gapItems`
- 草稿 / 结果混合态：`gapClosure.items`
- 匹配结果态：`selectionAnalysis.results`

说明：
当前闭环阶段同时承担编辑和结果保存语义，后续若继续深度治理，可进一步拆分为：
- `gapClosure.draft`
- `gapClosure.saved`

## 6. 后续开发的默认规则

后续如果新增编辑页或新增草稿功能，默认遵循：
1. 页面本地编辑态优先
2. 草稿态作为镜像
3. 结果态由明确动作产生
4. 持久化只跟随 Context 保存
5. 所有同步都必须先比较再更新

---

## 7. 当前结论

当前系统的状态同步架构已经具备明确分层：
- 本地编辑态
- Context 草稿态
- 结果态
- 持久化态

后续所有稳定性治理和功能开发，都应围绕这四层边界进行，而不是在页面中临时建立新的隐式同步链路。
